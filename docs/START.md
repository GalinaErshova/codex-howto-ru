## Как пользоваться руководством

Это самостоятельная русская адаптация учебного маршрута, объяснений и упражнений [Codex How To](https://github.com/Phelan164/codex-howto), а не официальный учебник OpenAI. Основа зафиксирована на коммите [`65e9712af333bea85f20030ed2b33b51308a228e`](https://github.com/Phelan164/codex-howto/tree/65e9712af333bea85f20030ed2b33b51308a228e). Структура из 14 модулей сохранена. Примеры для Bash переработаны для PowerShell; продуктовые рекомендации сверены с текущей официальной документацией.

В каждом модуле есть цель, объяснение, пример, упражнение и проверка понимания. Читайте столько, сколько нужно для текущей работы. Подключать все skills, плагины и серверы MCP не требуется.

Различайте три вида сведений:

- **Возможность продукта** — описана в официальном источнике, ссылка находится рядом с объяснением.
- **Учебная рекомендация** — выбранный в этом руководстве способ организации работы. Например, формат задания из четырёх полей или документ состояния не являются обязательными файлами Codex.
- **Проверено запуском** — конкретная локальная проверка, перечисленная в приложении «Проверка актуальности и отличия от исходника». Сверка с документацией сама по себе не означает успешный запуск команды, модели, MCP или облачного задания.

### Термины

| Термин | Значение в этом руководстве |
|---|---|
| Агент | Модель вместе с инструментами, окружением и правилами выполнения работы |
| CLI | Программа Codex, запускаемая из терминала |
| TUI | Интерактивный интерфейс CLI внутри терминала |
| Desktop | Настольное приложение; возможности и названия экранов зависят от версии |
| IDE | Расширение в редакторе кода |
| Sandbox, песочница | Ограничения ОС на доступ команд к файлам и сети |
| Approval | Разрешение на действие за пределами действующих границ |
| Skill | Инструкции для повторяемого процесса с файлом SKILL.md и, при необходимости, вспомогательными материалами |
| MCP | Протокол подключения внешних инструментов и данных |
| Hook | Обработчик события; может выполнять код отдельно от обычного ответа модели |
| Diff | Изменения между двумя состояниями файлов |
| Worktree | Отдельная рабочая копия одного Git-репозитория |
| Handoff | Передача задания или состояния с указанием проверяемых артефактов |

### Выберите маршрут

| Задача | Модули | Результат |
|---|---|---|
| Начать пользоваться Codex | 00 → 01 → 02 → 03 → 04 | Понятное задание, правильная папка, ограниченные права, проверенный результат |
| Разрабатывать приложение | Базовый маршрут → 05 → 07 → практикум | Небольшое исправление с воспроизведением и проверкой |
| Подключить инструменты или CI | Базовый маршрут → 06 → 11 → 12 | Один проверенный внешний инструмент либо пакетный запуск |
| Делегировать работу | 07 → 08 → 09 → 10 | Разделённые области ответственности и единая интеграционная проверка |
| Вести базу знаний | 04 → 10 → 13 | Документы с источниками, датами и понятным статусом |

На первый проход ориентируйтесь на несколько рабочих сессий. Временные оценки upstream — учебные ориентиры; скорость зависит от проекта и подготовки окружения.

**Если практика сейчас недоступна:** читайте основные модули вместе с разделом «Если практика недоступна: маршрут только для чтения». В нём 14 ситуаций с вопросами и объяснениями на русском, а также ссылки для углубления. В начале каждого модуля есть переход к соответствующему разбору. Этот маршрут не требует установки, терминала и доступа к модели; после скачивания Markdown-файлов его можно читать офлайн. [Открыть маршрут чтения](../READING.md).

### Перед первым запуском

1. Выберите небольшой репозиторий или учебную копию. Проверьте `git status --short --branch`.
2. Определите, где выполняются команды: Windows, WSL или облако. Папка и установленные инструменты должны соответствовать этой среде.
3. Запишите ожидаемое поведение и проверку готовности.
4. Начните с чтения проекта. Расширяйте права по реальной необходимости.
5. Если Codex уже установлен, используйте существующую установку; учебник не требует переустановки.



## Быстрый старт: одна полезная сессия

Проверьте терминал. Команды ниже ничего не устанавливают:

```powershell
$PSVersionTable.PSVersion
Get-Command codex -ErrorAction SilentlyContinue
Get-Command git -ErrorAction SilentlyContinue
git --version
```

Для установки через npm PowerShell может находить `codex.ps1` и `npm.ps1`. В этом случае `codex.cmd` и `npm.cmd` позволяют обращаться к соответствующим Windows-обёрткам. **У standalone-установки `codex.cmd` может не быть**: используйте найденный `codex.exe`. В последующих примерах обычное имя `codex` подразумевает работающую команду; при npm-установке можно заменить его на `codex.cmd`.

Откройте папку своего проекта вручную, затем:

```powershell
Get-Location
git status --short --branch
codex --version
codex --sandbox read-only --ask-for-approval on-request
```

В интерактивном Codex введите:

```text
Цель: объяснить, как собирать и проверять этот проект.
Контекст: начни с README, AGENTS.md и файлов конфигурации в корне.
Ограничения: только чтение; ничего не устанавливай и не меняй.
Результат: таблица «проверка → точная команда → папка запуска → файл-источник».
Если команду не удалось найти или выполнить, явно укажи это.
```

Для настольного приложения введите тот же текст в чате проекта. Флаги запуска относятся к CLI, а не к сообщению в чате. Режим доступа приложения выбирается его доступными средствами и политиками организации.

Проверьте ответ по файлам. Затем дайте маленькую задачу, например исправление опечатки или конкретного воспроизводимого дефекта. Назовите разрешённые файлы и критерий проверки. После изменения посмотрите `git diff --stat` и `git diff`. Эти команды показывают tracked-файлы; новые файлы проверяйте также через `git status --short`.

Готовность первой сессии: вы можете объяснить, какие файлы прочитаны, какие изменены, какая проверка действительно выполнена и что осталось неизвестным.
