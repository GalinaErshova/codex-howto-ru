## Шаблоны для ежедневной работы

### Задание на реализацию

```text
Цель: [конкретное изменение поведения].
Контекст: [проект, точка входа, требования и пример текущей ошибки].
Ограничения: [разрешённые файлы, совместимость, зависимости, публикация].
Готово, когда: [наблюдаемое поведение и проверки].
Сначала прочитай правила проекта и проверь ветку/рабочую копию.
Отчёт: результат, изменённые файлы, команды с исходом, непроверенное.
```

### Только исследование

```text
Изучи [вопрос] в [область проекта]. Только чтение.
Не устанавливай зависимости и не меняй файлы.
Верни вывод с путями и символами, подтверждённые факты отдельно от гипотез.
Назови следующий шаг, который позволит проверить оставшуюся неопределённость.
```

### Ревью фиксированного изменения

```text
Проверь diff [базовая ревизия → ревизия кандидата] по требованиям [ссылка].
Только чтение. Ищи ошибки поведения, несовместимость и пробелы проверок.
Для замечания: место, условие проявления, эффект, основание и способ проверки.
Не превращай предпочтения оформления в дефекты.
Если подтверждённых замечаний нет, скажи об этом и укажи ограничения ревью.
```

### Передача состояния

```text
Цель и границы:
Репозиторий / ветка / полный commit:
Изменённые файлы:
Подтверждённые решения:
Выполненные команды и результаты:
Непроверенное и причина:
Оставшиеся вопросы:
Следующее действие:
```

Названия `GOALS.md`, `PLANS.md`, `STATE.md`, `PROMPTS.md` и подобных файлов — соглашения команды. Codex не требует автоматически создавать каждый из них. Если документ состояния уже существует, обновляйте его. Источник: [официальный рецепт разработки](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex).
