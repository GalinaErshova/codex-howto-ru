# 13. Живая база знаний: сохранять проверенное

[← Предыдущий модуль](12.md) · [Оглавление](../README.md)

**Если сейчас только читаете:** [русский разбор ситуации без запуска программ](../READING.md#read-13). После него ответьте на вопросы самопроверки модуля; практическое упражнение можно отложить.

**Результат модуля:** вы умеете накапливать знания о Codex с источниками, датами и явным статусом. «Живая wiki» здесь — предлагаемый процесс ведения Markdown-документов, а не встроенная функция Codex с таким названием.

Удобная база начинается с небольшого указателя тем. Внутри каждой темы находятся проверенные утверждения, рекомендации, известные расхождения и открытые вопросы. Источник должен отвечать на вопрос «почему мы считаем это верным», а дата проверки — «насколько давно мы это установили». Количество заметок само по себе не делает базу полезной.

Локальная память Codex и документация команды решают разные задачи. Официальные документы рекомендуют хранить обязательные правила в `AGENTS.md` и версионируемых материалах, а память использовать для восстановления полезного контекста. Локальная память Codex отличается от памяти ChatGPT web; не предполагайте автоматическую синхронизацию этих хранилищ. [Memories](https://learn.chatgpt.com/docs/customization/memories).

### Минимальный формат

Для начала достаточно индекса, реестра источников и нескольких тематических страниц. Не добавляйте векторную базу, сервер или отдельный интерфейс до появления измеренной проблемы поиска. Это авторская рекомендация об объёме работы; продукт не требует такой архитектуры.

```text
knowledge/
  index.md
  sources.md
  topics/
    windows.md
    agents.md
  decisions/
    review-policy.md
```

Карточка источника может содержать устойчивый идентификатор, название, URL, тип источника, дату чтения, ревизию при наличии и перечень связанных тем. Не записывайте «официальный» для блога или GitHub-репозитория сообщества. Даже хороший сторонний пример остаётся сторонним примером.

```text
ID: official-subagents
Тип: официальная документация
URL: https://learn.chatgpt.com/docs/agent-configuration/subagents
Проверено: 2026-10-24
Связанные темы: agents, permissions
Статус вывода: подтверждено документацией; локально не испытано
```

Страница темы должна разделять три слоя: подтверждённое продуктовое поведение, решение команды и непроверенную идею. Например, «агенты наследуют разрешения родителя» — проверяемый продуктовый факт. «Для первого ревью используем одного помощника» — командная рекомендация. «Три помощника дадут лучший результат» — гипотеза до сравнения.

### Обновление без переписывания всей базы

Когда меняется официальный источник, найдите затронутые утверждения, обновите только их и объясните влияние на примеры. Если поддерживаются старые версии клиента, сохраните совместимость явной заметкой. Фраза «раньше было иначе» без версии и доказательства мало помогает читателю.

Поиск в учебной базе можно выполнить без специальных расширений:

```powershell
Get-ChildItem -LiteralPath '.\knowledge' -Filter '*.md' -Recurse |
    Select-String -Pattern 'sandbox', 'субагент', 'разрешения' |
    Select-Object Path, LineNumber, Line
git diff --check
git diff --stat
```

Существующий linter может проверить метаданные и локальные ссылки. Он не устанавливает, что источник действительно подтверждает фразу. Нужен отдельный смысловой просмотр: не расширен ли вывод, не потеряно ли ограничение платформы, не превратился ли эксперимент в обязательное правило.

### Пример задания Codex

```text
Прочитай индекс базы и найди знания о разрешениях субагентов.
Ничего не меняй. Ответь со ссылками на подходящие страницы.
Раздели официальное поведение, наши решения и открытые вопросы.
Если источники противоречат друг другу, покажи расхождение.
Не считай старую запись подтверждением текущего поведения.
```

### Упражнение

Выберите одно утверждение из учебника и проверьте его по текущей официальной странице. Подготовьте небольшую предлагаемую правку: старое утверждение, новое доказательство, затронутый пример и результат проверки. Затем отдельно решите, нужно ли менять правило проекта. Обновление знания и превращение его в обязательную инструкцию — два разных решения.

**Готово, когда:** темы находятся через индекс; у фактов есть источники и дата; рекомендации подписаны как рекомендации; устаревшие примеры помечены; смысловые изменения проходят ревью; тела сторонних материалов не копируются в репозиторий без основания.

**Самопроверка:**

1. Почему успешная проверка Markdown-ссылок не подтверждает достоверность текста?
2. Когда знание стоит перенести из wiki в `AGENTS.md`?
3. Чем гипотеза об эффективности отличается от измеренного результата?
