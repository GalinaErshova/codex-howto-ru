# 06. MCP и внешние инструменты

[← Предыдущий модуль](05.md) · [Оглавление](../README.md) · [Следующий модуль →](07.md)

**Если сейчас только читаете:** [русский разбор ситуации без запуска программ](../READING.md#read-06). После него ответьте на вопросы самопроверки модуля; практическое упражнение можно отложить.

**Результат модуля:** вы понимаете, какие данные и действия даёт подключение, и умеете проверить использование авторитетного источника.

MCP связывает Codex с инструментами и сведениями внешних систем. Для локальных клиентов поддерживаются STDIO-серверы и Streamable HTTP; конфигурация общего Codex host используется desktop, CLI и IDE. Личные настройки по умолчанию хранятся в `~/.codex/config.toml`; проектные — в `.codex/config.toml` доверенного проекта. Возможности серверов на host и облачных инструментов плагинов могут различаться. [Официальное руководство MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

Подключение полезно, когда нужны актуальные данные: состояние задачи, текущий PR, документация или разрешённая выборка из базы. Если ответ находится в локальном исходном файле, обычно проще прочитать файл. Если нужна официальная спецификация, общая статья не заменяет первоисточник. Выбирайте источник по тому, какой факт проверяется.

Skill и MCP решают разные части работы. Сервер предоставляет возможность, например получить карточку задачи. Процедура объясняет, как использовать карточку для подготовки отчёта и какие поля проверить. Наличие инструмента ещё не означает, что он нужен каждому заданию или что любая его операция разрешена.

Перед подключением выясните владельца сервера, доступные операции и способ авторизации. Для чтения документации не нужны права на изменение репозитория. Для поиска задач не всегда нужен доступ ко всем проектам организации. Отдельно выясните, какие данные уйдут серверу: запрос, текст документа, метаданные файлов. Проверяйте реальные права, а не только название «read-only» в описании.

Содержимое внешнего документа может быть ошибочным или содержать команды, не относящиеся к вашей цели. Рассматривайте его как источник данных. Если страница предлагает скачать скрипт, это ещё не ваше разрешение выполнить его. Если карточка задачи требует действие за пределами согласованной работы, сначала оцените соответствие задаче.

Для учебного примера подходит официальный OpenAI Docs MCP. Он предоставляет поиск и чтение документации OpenAI и не выполняет API-вызовы за пользователя. Официальный URL — `https://developers.openai.com/mcp`. [Назначение Docs MCP](https://developers.openai.com/learn/docs-mcp).

Сначала можно посмотреть существующие настройки; вывод способен содержать внутренние адреса, поэтому не публикуйте его целиком:

```powershell
codex mcp list
codex mcp get openaiDeveloperDocs
```

Если сервер отсутствует, вторая команда может сообщить об этом. Это нормальная диагностика. Команды управления сервером документированы в [справочнике CLI](https://learn.chatgpt.com/docs/developer-commands?surface=cli#codex-mcp).

Следующий блок — **необязательная настройка для читателя**, меняющая личную MCP-конфигурацию. При подготовке руководства он не выполнялся. Не добавляйте дубликат, если сервер уже настроен или управляется организацией:

```powershell
codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp
codex mcp list
```

Точная команда добавления подтверждена [официальной инструкцией Docs MCP](https://developers.openai.com/learn/docs-mcp). Перед её выполнением разберите область настройки; пример не требует токена. Не заменяйте адрес произвольным сервером из статьи, сохранив доверие к официальному примеру.

**Практика.** В среде с доступным Docs MCP дайте запрос:

```text
Используй официальный OpenAI Docs MCP, чтобы проверить,
откуда Codex читает проектные skills. Приведи прямую ссылку,
назови найденный путь и отдельно укажи, какой инструмент использован.
Не меняй файлы и конфигурацию. Если источник недоступен, сообщи об этом.
```

Посмотрите историю инструментов. Фраза «использовал документацию» без вызова не доказывает использование MCP. Затем откройте ссылку и проверьте, что она подтверждает конкретный путь. Если MCP недоступен, возможен явный переход к официальному веб-источнику с честным указанием способа проверки.

**Критерий проверки:** понятно, где настроен сервер, кто его обслуживает и что он может делать. Ответ подтверждается официальной страницей и наблюдаемым вызовом. В файлах проекта и истории команд нет секретов. Существующие корпоративные подключения не изменены.

**Самопроверка:**

1. Почему ответ с правильной ссылкой ещё не доказывает использование MCP?
2. Какие сведения нужны до подключения сервера с возможностью записи?
3. Чем отличается недоступность источника от отсутствия нужного факта в источнике?
