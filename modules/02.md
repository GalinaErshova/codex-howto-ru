# 02. CLI и первые шаги в Windows

[← Предыдущий модуль](01.md) · [Оглавление](../README.md) · [Следующий модуль →](03.md)

**Если сейчас только читаете:** [русский разбор ситуации без запуска программ](../READING.md#read-02). После него ответьте на вопросы самопроверки модуля; практическое упражнение можно отложить.

**Результат модуля:** вы проверили локальное окружение и завершили одну небольшую правку с понятным diff.

CLI работает в терминале и использует установленное на компьютере окружение. Первый запуск выполняется из каталога проекта; доступные способы входа показываются при авторизации. Установка CLI, установка настольного приложения и установка IDE extension — отдельные действия. Для Windows официально документированы самостоятельный установщик и вариант через npm. Ниже показан npm-вариант для компьютера, где Node.js и npm уже установлены. [Установка CLI](https://learn.chatgpt.com/docs/codex/cli).

```powershell
# Только проверка существующих программ
$PSVersionTable.PSVersion
Get-Command git, node, npm.cmd -ErrorAction SilentlyContinue
git --version
node --version
npm.cmd --version
```

Если программы нет, сначала решите вопрос её установки обычным для вашей организации способом. Пропуск команды не делает окружение готовым. Важно знать, какая программа запускается: несколько установок Node.js или старый путь в `PATH` могут объяснить различия между двумя терминалами.

Если выбран официальный npm-способ установки, читатель выполняет:

```powershell
npm.cmd install -g @openai/codex
```

Здесь `npm.cmd` явно выбирает Windows-обёртку npm. Это удобно, когда запуск `npm.ps1` ограничен execution policy. Для данного учебного пути не нужно менять политику выполнения PowerShell. Установка изменяет пользовательское окружение; в процессе подготовки руководства она не выполнялась.

После установки откройте новый терминал и проверьте:

```powershell
Get-Command codex -All
codex --version
```

Если npm установил `codex.cmd`, а PowerShell выбирает запрещённый скрипт `codex.ps1`, используйте `codex.cmd` вместо `codex` в последующих примерах. При самостоятельной установке может быть доступен исполняемый файл. Опирайтесь на результат `Get-Command`, а не на предположение о способе установки.

Перед запуском в реальном проекте проверьте путь и Git:

```powershell
Set-Location -LiteralPath 'C:\Work\sample-project' -ErrorAction Stop
git rev-parse --show-toplevel
git branch --show-current
git status --short
```

`C:\Work\sample-project` — пример: подставьте существующий путь вашей учебной копии. Если есть чужие незакоммиченные изменения, выясните их происхождение. Не очищайте рабочую папку ради красивого статуса. Для упражнения выберите собственную ветку и небольшой независимый файл.

В интерактивном CLI документированы `/init` для начального `AGENTS.md`, `/status` для параметров сеанса, `/permissions` для разрешений, `/review` для просмотра изменений и `/plan` для планирования. Slash-команды вводятся внутри Codex, а не в PowerShell. Их доступность и поведение сверяют со страницей именно CLI. [Справочник команд](https://learn.chatgpt.com/docs/developer-commands?surface=cli).

**Практика.** Запустите CLI из учебной копии и дайте задание:

```text
Найди в README один абзац, который неточно описывает текущий код.
Сначала проверь реализацию, затем исправь только этот абзац.
Не меняй поведение программы, зависимости и другие файлы.
Покажи, чем подтверждён новый текст, и выполни существующую
проверку документации, если она есть.
```

После завершения проверьте результат самостоятельно:

```powershell
git diff --stat
git diff -- README.md
git status --short
```

Если команды проверки документации нет, честный результат — «проверены текст и diff; автоматическая проверка документации в проекте не найдена». Не требуйте фиктивного зелёного статуса. Если изменилось больше файлов, выясните причину до принятия результата.

**Критерий проверки:** установлено, какая оболочка и версия CLI используются; вход выполнен вашим разрешённым способом; изменён ровно согласованный фрагмент; реализация подтверждает новый текст. Незапущенные проверки перечислены отдельно.
